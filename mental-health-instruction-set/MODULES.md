The 34 dropped lenses are pinned as one span (`clinical:dropped-lenses`), so any change inside them, including text added after lens 40, stops the build.

## Assembly

`INSTRUCTION_SET.md` is assembled exactly as R11's `Tools/release_common.py` does it:

- same module order, anchors and `---` separators;
- module links, and the Grid's mermaid click targets, rewritten to in-page anchors;
- professional-module process maps (mermaid) omitted from the core, keeping only the two Grid maps.

The `modules/` copies keep their process maps and file-style links.

The build proves this: it assembles the unedited R11 modules with the same code and requires the result to equal R11's `INSTRUCTION_SET.md` byte for byte.

## Build checks

Every check must PASS or the build exits non-zero and writes nothing:

1. Assembler reproduces the R11 core byte for byte from unedited R11 modules.
2. Lens anchors are exactly the six kept lenses, once each.
3. No duplicate anchors.
4. Every link is external or resolves to an anchor in the core.
5. Grid click targets exist and are in-page anchors (and at least one exists).
6. No module-file link or click target remains in the core.
7. Only the two Grid maps remain in the core.
8. The Rules are not embedded in the core.
9. No dropped lens, dropped service or media-production term remains in any module or the Rules, apart from the reviewed uses below.

### Reviewed and left unchanged

These were flagged in review and kept on purpose:

- Evidence: "Operations supplies the available representation and any requested display." Operations: "a supported display route supply a visual result." Both are conditional on what the deployment exposes.
- Engine: "Psychological, psychiatric and functional perspectives…". "Functional" reads as everyday functioning, not as the dropped Occupational Therapist lens.
- Operations still describes web search, the browser and the medical library as connection classes. The text depends on what the application actually exposes, so with those capabilities off the model has to report the limitation (see `HARNESS_REQUIREMENTS.md`).

## What the build does not establish

The build cannot tell whether any clinical statement is correct, current or complete. R11 states that clinical source currency was not revalidated, and these removals do not change that.
